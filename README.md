- **Що не вийшло або забрало найбільше часу:** Відстеження зміни HP через вікно `Console` (`Debug.Log`), а також розв'язання конфліктів злиття (Merge Conflicts) під час синхронізації з GitHub.
- **Що зрозуміла про тригери, public і private:** Тригер (`Is Trigger`) пропускає об'єкт крізь себе та викликає події дотику замість фізичного блокування; `public` робить змінні доступними в Inspector та для інших скриптів, а `private` захищає дані всередині файлу.
- **Яке значення Time Invincible обрала і для якого гравця:** Обрала **2.0 секунди**, щоб гравець мав достатньо часу вийти із зони шкоди і не втрачав усе здоров'я миттєво.

**Що зроблено:**
Лабораторна 7: власний рівень на спільній базі (сцена `MyLevel` у темі «болото й кам'яна доріжка»), винесено поля `amount` та `damage` в інспектор, створено червоний варіант ворога `EnemyFast`, оновлено репліку жаби-NPC та проведено плейтест.

**Три ділянки мого рівня і чим вони відрізняються:**
1. *Ділянка 1 (легка — знайомство):* старт і NPC-жаба зліва (озвучує мету зрізу), один базовий ворог (`Enemy`) на короткій кам'яній доріжці та аптечка (`amount = 1`) після нього.
2. *Ділянка 2 (середня — практика):* другий базовий ворог біля озерця з водою, поруч зона шкоди (`DamageZone` з `damage = 1`), яку можна обійти, та посилена аптечка (`amount = 2`) як нагорода після перешкоди.
3. *Ділянка 3 (важка — перевірка):* вузька кам'яна доріжка з водою по боках, де патрулює швидкий варіант ворога (`EnemyFast`), що вимагає точного таймінгу.

**Варіант ворога і чим він відрізняється:**
Створено Prefab Variant `EnemyFast` від базового префаба `Enemy`. Колір `Sprite Renderer` змінено на червоний як сигнал підвищеної загрози. Параметри руху змінено з `Speed = 2, Change Time = 3` на `Speed = 4, Change Time = 1.5`, щоб ворог рухався вдвічі швидше, але зберігав ту саму довжину маршруту і не сходив у воду.

**Що показав плейтест і що я змінив у числах:**

Під час налаштування підібрано `Speed = 4` та `Change Time = 1.5` для `EnemyFast`, щоб його траєкторія точно вкладалася у вузьку кам'яну доріжку, а для другої аптечки встановлено `amount = 2`, щоб компенсувати можливу шкоду від `DamageZone` (`damage = 1`).
